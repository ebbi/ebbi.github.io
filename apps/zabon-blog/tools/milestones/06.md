# Milestone 06: Navigation & Header

## Scope fence (read first)

06 is a **navigation / URL** milestone. It does NOT translate content, does
NOT filter content by language, and does NOT introduce per-language post
files. It builds a header + a language switcher that change the URL hash
while preserving the current view (list stays a list; a post stays that
same post slug). Rendering *translated* bodies is a later milestone.

## Objective

Replace the minimal header currently in `index.html` with a structured,
responsive `<header>` containing a brand region and a language switcher
for the four **content** languages (`en`, `fa`, `ar`, `th`).

Selecting a language updates the URL hash while preserving the view:
- list to list:  `#/en`             to `#/fa`
- post to post:  `#/en/post/<slug>` to `#/fa/post/<slug>`

RTL/LTR is applied by `router.js` (it already sets `dir` on `<html>`); 06
does NOT recompute `dir`. Header CSS uses logical properties so it lays
out correctly under either `dir`.

## Interfaces (mandatory)

### New: `apps/blog/assets/js/nav.js`

    window.BlogNav = {
      init(router): void,
      onRouteChange(route): void
    };

- `init(router)` - called once by `app.js` after data load. Stores the
  router reference. Does NOT parse `location.hash`.
- `onRouteChange(route)` - called by `app.js` every time the router emits
  a route. Route is the router's own vocabulary:
  `{ lang, type: 'list'|'post', slug, raw }` (see HANDOFF-05b-removal.md,
  decision V1). Used to (a) mark the active language with `aria-current`,
  and (b) rebuild each language link's `href` so post-to-post preserves
  the slug.

Language constant (single source within 06):

    const LANGS = [
      { code: "en", label: "EN", dir: "ltr" },
      { code: "fa", label: "FA", dir: "rtl" },
      { code: "ar", label: "AR", dir: "rtl" },
      { code: "th", label: "TH", dir: "ltr" }
    ];

The four CONTENT languages shipped today. LOCKED_DECISIONS.txt lists eight
UI languages (en, fa, th, ar, my, es, ja, zh); the switcher shows only the
content set. A future milestone may widen this without a rewrite.

URL construction rule (the crux):

Given the current `route`:
- if `route.type === 'post' && route.slug`:
  target = `#/<code>/post/<route.slug>`
- else:
  target = `#/<code>`

This is the ONLY place the app builds a language-switch URL. No
`location.hash` string surgery anywhere in `nav.js`.

### Modified: `apps/blog/assets/js/app.js`

- After `BlogRouter.init(handleRouteChange)` succeeds, call
  `BlogNav.init(window.BlogRouter)` exactly once.
- In `handleRouteChange(route)`, after dispatching to `renderList` /

- Guard both calls: if `window.BlogNav` is absent, log and continue. The

## Accessibility requirements

- Language switcher is a `<nav>` with `aria-label="Language"`.
- Active language link carries `aria-current="true"` (or `"page"`).
- Language links are real `<a>` with `href` (keyboard-operable by default).
  No JS-only `<button>` that swallows navigation.

## Decisions frozen for this milestone

- **N1:** 06 is navigation-only; no translation, no language filtering,
  no content-file changes.
- **N2:** `nav.js` derives every language URL from the router's route
  object. It never parses `location.hash`.
- **N3:** The header receives routes via `BlogNav.onRouteChange(route)`
  forwarded from `app.js`'s existing router callback. No second
  `hashchange` listener, no private state.
- **N4:** RTL is owned by `router.js` (sets `dir` on `<html>`); `nav.js`
  and the CSS do not compute it. CSS uses logical properties.
- **N5:** Switcher language list is the four CONTENT languages; the set
  lives in one constant in `nav.js`.

## Known issues the next chat must NOT mistake for bugs

- Post slugs are language-agnostic (`LOCKED_DECISIONS.txt`). So
  `#/fa/post/<en-slug>` routes to a post and renders its existing body
  (currently EN text) under an `fa` URL. Expected until translated
  content exists.
- `posts.json` is EN-only today, so `#/fa` and `#/th` render the empty
  list state. Expected; not a regression.
- RTL set membership is a literal in `router.js` and is not recorded in
  `LOCKED_DECISIONS.txt`. Out of scope for 06; note in handoff.
