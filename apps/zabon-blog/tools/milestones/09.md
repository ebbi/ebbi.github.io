# Milestone 09: Single Post Page

## Scope fence (read first)

09 makes the single-post view (route type `post`) a finished, styled page:
it owns `renderPost` in app.js and everything it emits — the header
(title + meta line), the 404 not-found block, and the `post-detail` /
`post-content` wrappers — plus the CSS block that styles them. 09 does
NOT add or change block-type rendering (that is B1, which depends on 09),
does NOT touch `renderList` or the list styles from 08, does NOT introduce
a date formatter (owned by 11), does NOT touch the router, and does NOT
change the data contract (posts.json + feed.json remain interim until C1).

## Objective

Navigating to `#/<lang>/post/<slug>` renders a styled single-post page:
a header with the post title and a `<date> • <LANG>` meta line, followed
by the post body rendered by `BlogRenderer.render`. The header uses the
same namespaced class convention established by 08 (L-3), so the list and
post views share one naming vocabulary. A missing slug renders a styled
404 block with a working link home.

## Decisions frozen for this milestone

- **D1. renderPost header adopts namespaced classes** —
  `.post-header__title` and `.post-header__meta`, mirroring 08's
  `.post-list-item__title|__meta` (L-3). Rationale: 08's bare
  `post-meta` was a scoping artifact, not a design; one naming
  vocabulary across both views. From 09 onward, `.post-header__meta`
  supersedes the bare `post-meta` class. Downstream (11, 12a) may rely
  on this.
- **D2. Date formatting stays out of 09.** Both views continue to emit
  the raw ISO string from posts.json/feed.json. The correct fix is
  locale-aware `Intl.DateTimeFormat` applied in BOTH `renderList` and
  `renderPost`; it is owned by milestone 11 (Translations & i18n UI),
  per 08's Option A. 09 must not introduce `slice(0,10)`, `Date#toDateString`,
  or any other partial formatter.
- **D3. Slug is language-agnostic.** `#/<lang>/post/<en-slug>` renders
  the EN body. No per-language slug resolution is added here.
- **D4. Block rendering is delegated, not reimplemented.**
  `window.BlogRenderer.render(post.blocks, contentEl)` remains the call
  site; the minimal text fallback stays as-is. Any block-type work is
  B1.
- **D5. `renderList` is frozen.** No changes to the 08 list view or its
  classes.
