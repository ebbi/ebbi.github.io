## Why this exists (re-scope of C1b-09)

The original C1b-09 plan was a single SEAM-EXTENSION milestone: freeze the
embed shape as D-Tool-21, then migrate part-17 (Algeria #2). Recon on the
live part-17 HTML (WORKFLOW step 0 / pre-flight of this chat) refuted the
plan in three ways and tripped the milestone's own boundary ("If a NEW
structural class beyond embed appears, STOP and re-scope (its own
milestone)"):

1. The embed wrapper is NOT `wp-block-embed`. It is the legacy Jetpack
   wrapper:
   `<div class="jetpack-video-wrapper"><span class="embed-youtube"
   style="…"><iframe class="youtube-player" …></iframe></span></div>`.
   part-17 carries FOUR of them, not the one posts.json advertises.

2. A SECOND new class beyond embed exists on every C1b series post: the
   legacy caption-shortcode figure
   `<figure … class="wp-caption aligncenter"><img …><figcaption
   class="wp-caption-text">…</figcaption></figure>`. The frozen seam has no
   rule for it, so its `<img>` is silently dropped.

3. Consequence 2 is a PRE-EXISTING, UNRECORDED silent loss across the
   already-shipped slugs (NEW-1/NEW-2 prohibit silent loss). Spot-checks
   (live `entry-content` bodies vs committed files):
     - part-22: 13 body imgs, 9 wp-caption figs -> committed file has 4 images.
     - part-18: 14 body imgs, 7 wp-caption figs -> committed file has 7 images.
     - part-20: 12 body imgs, 9 wp-caption figs -> committed has 3 images.
     - part-21: 19 body imgs, 14 wp-caption figs -> committed has 5 images.
     - part-19: 17 body imgs, 14 wp-caption figs -> committed has 3 images.
   Prior handoffs' "census matched recon byte-identical" is true but circular:
   recon used the same defective seam, so it validated the seam against itself.

Therefore C1b-09 splits into two milestones (decision of the maintainer,
Option A):
  - C1b-09a (THIS): freeze BOTH new representations, record the discovered
    losses, and RE-MIGRATE the affected shipped slugs so the deployed corpus
    is faithful. No NEW slug is introduced here.
  - C1b-09b: migrate part-17 once the seam is complete.

## Decisions frozen for this milestone

### D-Tool-21 — legacy Jetpack embed (WP.com `core/embed` output)

`extractHtmlBlocks()` TOP list gains an entry, placed AFTER `footnotes` and
BEFORE `paragraphBare`, matching
`/<div\b[^>]*class="[^"]*\bjetpack-video-wrapper\b[^"]*"[^>]*>[\s\S]*?<\/div>/i`,
kind `"embed"`, handled in `blockFromFragment()` by emitting
`{ type:"embed", content:<the inner <iframe …></iframe> markup, verbatim> }`.
Rationale: WP.com renders embeds as `div.jetpack-video-wrapper >
span.embed-youtube > iframe`; the frozen seam had no rule, so the loop's
skip-and-advance logic dropped the whole embed tag-by-tag (L-004..L-006:
"extraction seam cannot extract core/embed"). renderer.js ALREADY consumes
`type:"embed"` (LOCKED_DECISIONS block-types list). Entities in the iframe
`src` (`&#038;`) are PRESERVED verbatim per D-Tool-15/D-Tool-16.

### D-Tool-22 — legacy `figure.wp-caption` caption image

`extractHtmlBlocks()` TOP list gains an entry, adjacent to `imageFig`,
matching
`/<figure\b[^>]*class="[^"]*\bwp-caption\b[^"]*"[^>]*>[\s\S]*?<\/figure>/i`,
kind `"wpCaptionFig"`, handled in `blockFromFragment()` by reusing the
existing image path: `{ type:"image", src:<img src verbatim>,
caption:<inner HTML of the first <figcaption>, via captionOf()> }`.
Rationale: legacy WP.com caption-shortcode markup
(`<figure data-shortcode="caption" class="wp-caption aligncenter">…`) is
present in EVERY C1b series post but matched NO TOP entry, so the loop
skipped it and its `<img>` was silently lost (unrecorded until now). This is
the SAME shape of defect as L-009 (bare `<p><img>`, D-Tool-20): a legacy
image markup class the seam did not model. Caption convention matches the
existing `imageFig` path (captionOf: figcaption inner HTML, trimmed, outer
`<em>` unwrapped, entities preserved).

  images + 1 embed; the LIVE post has 4 embeds and 13 images of which 6 are
  wp-caption figures. Trust only the live HTML.

  faithful, not losses. Inline `<em>`/`<strong>` in paragraphs likewise.
