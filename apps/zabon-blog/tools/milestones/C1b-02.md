# Milestone C1b-02: Migrate `update` from the live HTML extraction

## Scope fence (read first)

This milestone migrates ONE EN post — slug `update` — from the LIVE HTML
extraction (--from html) into content/en/update.json, and proves fidelity
against its live census. It is the second migration in the C1b-01..19 series.
It is deliberately the smallest post in the corpus (2 blocks, no images,
no embeds, no quotes, no tables, no footnotes) — a confidence-builder that
exercises the whole migration pipeline (import → census → content file →
regenerate feed.json → integrity) after C1b-01's cite-carrying-quote fix.
It does NOT migrate any other post. It does NOT add core/embed support
(LOSS_LEDGER L-004..L-006 remain deferred). It does NOT touch the seam.

## Objective

After this milestone:

- apps/blog/content/en/update.json exists, produced by
  `import-post.js --from html` from the live `update` post URL, in the
  C1a-locked shape { slug, lang, title, date, blocks } with no `excerpt`.
- The content file's blocks.length and block-type census match the live
  HTML extraction exactly. Any mismatch is recorded in LOSS_LEDGER.md,
  never reconciled silently (NEW-1/NEW-2).
- apps/blog/assets/data/feed.json is regenerated (3 entries).
- apps/blog/tools/test-integrity.js prints INTEGRITY OK.
- The next milestone (C1b-03) is authored at this chat's close.
