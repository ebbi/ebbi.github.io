# Milestone C1: Content migration (posts.json -> content/<lang>/<slug>.json)

## Scope fence (read first)

C1 replaces the interim single-file data source (assets/data/posts.json
+ feed.json) with per-post, per-language files under
content/<lang>/<slug>.json, and rewires the app fetch path to read them.
C1 is a CONTENT/DATA milestone: it moves where post data lives and how
the app loads it. C1 does NOT add or change block-type rendering (B1),
does NOT touch renderList/renderPost presentation or classes (08/09),
does NOT introduce a date formatter (11), does NOT change the router
vocabulary, and does NOT touch the renderer. The interim posts.json and
feed.json may remain on disk as a fallback during C1 (see D3) but are no
longer the canonical source.

## Objective

Per-post, per-language JSON under content/<lang>/<slug>.json is the
canonical content source (as LOCKED_DECISIONS Recovery requires). The app
loads the pilot post from its content file at runtime; the list and post
views render identically to 08/09 using the new source. A missing
language file degrades to the non-EN empty state (carried from 08 L-4),
not an error.

## Decisions frozen for this milestone

- C1-D1. Canonical path is content/<lang>/<slug>.json (per
  LOCKED_DECISIONS Recovery). posts.json/feed.json cease to be canonical.
- C1-D2. Single filter site preserved (L-2); renderList remains the only
  posts.filter. The index carries no presentation logic.

  fallback; their deletion is a separate, later cleanup milestone.
- C1-D4. Presentation is frozen: no class or markup change in
  renderList/renderPost (08/09 outputs stand).
