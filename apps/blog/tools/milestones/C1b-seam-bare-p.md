# Milestone C1b-seam-bare-p: Represent bare-<p> bodies in the extraction seam

## Scope fence (read first)

This milestone extends the D-Tool-9 extraction seam in
apps/blog/tools/import-post.js so that extractHtmlBlocks/blockFromFragment
can represent a bare `<p>` element that sits DIRECTLY inside entry-content
and carries NO `wp-block-paragraph` class. This is a second narrow
extension of the seam freeze; the first was D-Tool-18 (quote-cite).
It is NOT a re-scoping of C1b-02. C1b-02 remains blocked until this lands;
this milestone's own closing action is to migrate the `update` post and
prove its live census (2 blocks; LOSS_LEDGER L-008), which re-opens and
completes C1b-02's goal. It does NOT add core/embed support (L-004..L-006
remain deferred). It does NOT change any exported signature.

## Objective

After this milestone:

- The extraction seam recognises bare `<p>` elements directly inside
  entry-content, and only there: it must NOT re-capture `<p>` elements that
  live inside already-consumed wrappers (a `<blockquote>`, a
  `<figure>` caption, etc.). The D-Tool-9 skip-and-continue loop already
  consumes wrapper blocks whole, so this is achieved by adding a bare-<p>
  entry to the TOP list whose regex requires the class attribute to be
  absent OR to lack `wp-block-`; the existing loop then consumes each match
  exactly once, left-to-right.
- apps/blog/content/en/update.json exists, produced by
  `import-post.js --from html` from the live update URL, in the
  C1a-locked shape { slug, lang, title, date, blocks }, no `excerpt`,
  census { paragraph: 2 }.
- apps/blog/assets/data/feed.json regenerated (3 entries).
- apps/blog/tools/test-integrity.js prints INTEGRITY OK.
- LOSS_LEDGER L-008 moves open -> resolved.
- LOCKED_DECISIONS gains D-Tool-19 (the bare-<p> rule), appended.
- The next milestone (C1b-03) is authored at this chat's close.

## Interfaces (mandatory)

### Modified: apps/blog/tools/import-post.js

    The ONLY change is inside extractHtmlBlocks: the TOP list gains one
    entry for a bare paragraph. It must match a <p ...> tag whose class
    attribute either is absent, or (if present) does NOT contain
    `wp-block-`. It must NOT match the existing
    `wp-block-paragraph` entry (already present) and must NOT re-match
    quote-internal <p> elements (they are inside a <blockquote> the loop
    consumes first).

    Sketch of the entry (kind name to be finalised in the diff):

      {
        re: /<p\b(?![^>]*\bclass="[^"]*\bwp-block-)[^>]*>[\s\S]*?<\/p>/i,
        kind: "paragraphBare",
      }

    blockFromFragment must handle kind "paragraphBare" identically to
    "paragraph": strip tags, keep entities, TRIM. Emitted shape is the
    unchanged D-Tool-15 paragraph: { type:"paragraph", content:<str> }.

    No new exported symbols. No change to buildContentFile, extractBlocks,
    fetchRaw, parseArgs, main, or any signature.

- D-Tool-19 (new): bare-<p> rule for the D-Tool-9 seam — see the
  LOCKED_DECISIONS append in Test Checklist step 7. Rationale: some live
  posts (L-008, `update`) render their body as bare `<p>` with no

  inside entry-content; it does NOT re-capture wrapper-internal <p>.
  Recorded as the second deliberate, narrow extension of the D-Tool-9
  freeze (first was D-Tool-18).

## Known issues the next chat must NOT mistake for bugs

- The bare-<p> rule is narrow. It will NOT capture `<p>` with a
  `wp-block-*` class (the existing TOP entry owns those), and it will
  NOT re-capture `<p>` nested inside a `<blockquote>`/`<figure>`/
  `<div class="wp-block-*">` (the wrapper entry consumes them whole,
  left-to-right, before the bare-<p> entry can match).
- core/embed is still intentionally unhandled; L-004..L-006 remain
  deferred. Do not migrate one of those slugs until an embed-seam
  milestone lands.
- posts.json is UNTRUSTED; the migration SOURCE is the live HTML, never
  posts.json. Its `update` entry is not authoritative.
- The IDE Apply mechanism injected a stray label token into JS in C1b-01.
  If you edit import-post.js (you will, this milestone), inspect
  `git diff` at the patch site before running the tool. A green
  `node --check` is NOT proof the patch matched intent.
- test-integrity.js does not cover content/, feed.json, or the seam.
