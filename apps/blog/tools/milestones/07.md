# Milestone 07: Footer & Global UI

## Objective

Implement the global footer, loading states, and a basic offline/fallback UI. This ensures the app feels polished and provides feedback to the user during async operations (like initial data fetching).

## Files to Create

1. `apps/blog/assets/js/global-ui.js`

## Files to Modify

- `apps/blog/index.html` (Add a `<footer>` element and a global loading spinner/container).
- `apps/blog/assets/css/style.css` (Add styles for the footer, loading spinner, and basic layout spacing).
- `apps/blog/assets/js/app.js` (Hook into the fetch process to show/hide the loading state).

## Files I will NOT touch

- Any files outside `apps/blog/`.
- `apps/blog/tools/` (Node.js tooling).
- `apps/blog/assets/data/` (Data files).

## Hard Constraints (from LOCKED_DECISIONS.txt)

- **Vanilla JS only**: No frameworks.
- **Loading State**: A simple CSS-based spinner or "Loading..." text must be visible in the `#app` container while `app.js` is fetching `posts.json`. It must disappear once data is loaded or if an error occurs.
- **Footer Content**: Must include a copyright notice and a link back to the main Zabon app (`../../index.html`).
- **CSS Logical Properties**: Use `padding-inline`, `margin-inline`, etc., to ensure the footer and global spacing automatically mirror correctly when `dir="rtl"` is active.

## Test Checklist

1. **File Tree Check**:
   - Run: `ls apps/blog/assets/js/global-ui.js apps/blog/assets/css/style.css apps/blog/index.html`
2. **Syntax Check**:
   - Run: `node -c apps/blog/assets/js/global-ui.js`
3. **Manual Browser Check**:
   - Open `apps/blog/index.html`.
   - Open DevTools -> Network tab. Set throttling to "Slow 3G".
   - Reload the page. Verify the loading state is visible.
   - Once loaded, verify the loading state disappears and the footer is visible at the bottom of the page.
   - Verify the footer link to the main Zabon app works.
