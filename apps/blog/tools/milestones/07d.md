# Milestone 07d: CSS typography update (book-reader pass)

## Scope fence (read first)

This milestone is a TYPOGRAPHY pass over the existing reading experience: it
tunes the CSS that already styles the post body, list, and chrome so the app
reads like a BOOK rather than a generic web page. It touches
`assets/css/style.css` (additive token + rule updates only) and the
ROADMAP/CURRENT pointer. It does NOT touch the extraction seam
(`tools/import-post.js`, frozen through D-Tool-29), any `content/**/*.json`,
`feed.json`, `renderer.js` block mappings, `router.js`, `app.js` render logic,
`nav.js`, `shell.js`, `theme.js`, TTS/`tts.js`, or font FAMILY selection (that
is 07c). It must NOT change the meaning of any existing class, and must NOT
remove or rename existing CSS custom properties — it may ADD tokens. It is a
visual/typographic milestone: no new routes, no new modules, no behaviour
change.

Relationship to 07c: 07d sets the typographic SYSTEM (measure, rhythm, scale,
spacing, hyphenation) using the existing `--font-*` family tokens; 07c lets the
reader CHOOSE which font FAMILY feeds those tokens. Do 07d first (system), then
07c (family choice). 07c depends on 07d.

## Objective

When this milestone is done:

- the reading column has a comfortable MEASURE (line length ~60–75 characters)
  and the post body reads with a clear vertical rhythm,
- line-height, paragraph spacing, and block spacing produce even, book-like
  reading density (no cramped or double-spaced paragraphs),
- the heading scale (h1–h4) is coherent and proportional to the body text,
- long-form elements read well: `blockquote`, inline `code` / `pre`, `table`,
  `figure`/`figcaption`, lists, links, and `hr`,
- hyphenation / word-breaking is enabled appropriately for the body (and never
  breaks code), with a `prefers-reduced-motion`-independent, RTL-safe setup,
- the changes are ADDITIVE and token-driven: existing class names and existing
  token names keep their meaning; new tokens are added only,
- both themes (day/night) remain legible; RTL direction is unaffected,
- and the list view, toolbars, and drawer keep their current layout (only
  typographic details may improve).

## Interfaces (mandatory — a milestone without these is not ready)

### Modified: apps/blog/assets/css/style.css

    A single additive "Milestone 07d — typography" block (and, where needed,
    additive token additions in :root / html[data-theme="night"]).
    Contract:
      - New/used tokens (additive; keep existing names working):
          --font-body, --font-heading, --font-mono   (family tokens; 07c sets
                                                       which family body uses)
          --font-size-base, --line-height-base, --measure, --rhythm
          --space-1..--space-6                        (if not already present)
      - Body: max-inline-size = --measure; margin-inline auto; font-size and
        line-height from tokens; text-wrap: pretty where supported.
      - Headings: size scale derived from --font-size-base; text-wrap: balance
        where supported.
      - Blockquote/code/pre/table/figure: spacing + size from tokens; code and
        pre NEVER hyphenate (overflow-wrap: normal for code; allow scroll).
      - Hyphenation: hyphens: auto on body prose with a lang attribute present;
        disabled for code/pre.
      - Logical properties only (margin-inline, padding-inline, max-inline-size)
        for RTL safety.
    Edits/renames NO existing class; removes NO existing token.

### Unchanged (must remain): class NAMES and tokens consumed by renderer.js

    renderer.js emits specific class names for blocks (post-content, headings,
    blockquote, code/pre, table, figure). 07d styles those by ADDING tokens/
    rules; it must not rename them (renderer.js is out of scope).
