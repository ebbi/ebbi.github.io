# Milestone 08: Post List Page

## Scope fence (read first)

08 turns the home/list view into a real, presentable post list. It owns
the list _view_ only: the markup produced by `renderList` in `app.js`,
the `post-list` / `post-list-item` structure, and the CSS for that
structure. It is a presentation + wiring milestone.

08 does NOT: change the data contract (`posts.json` + `feed.json`
remain the interim source; C1 converts later); add or translate content;
add route types or touch router.js; touch renderer.js or any block
rendering; introduce search, pagination, or filtering beyond the existing
per-language filter; add theme/font/TTS behavior; or perform a formal
accessibility or performance audit (13a/13b/13c).

The non-EN empty state is CARRIED, not fixed. `posts.json` is EN-only;
`#/fa` and `#/th` legitimately render no posts until translated content
lands (C1/11). 08 must render that state gracefully but must NOT invent
content or a fallback list.

## Objective

When this is done:

- the list view renders every post visible for the current route
  language as a consistent, styled list item (title link, date, language
  code, excerpt),
- the empty state for a language with no posts is a clean, centered
  message (no broken layout, no console errors),
- the existing per-language filter behavior is preserved and is the
  single place list filtering happens,
- list markup is built from the merged post objects (body + excerpt)
  already produced by `mergePostsAndFeed`, and
- the list is responsive at the existing breakpoints (mobile-first).
