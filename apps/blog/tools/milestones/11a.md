an API key in an env var, translates an EN envelope into a target-language
envelope with the SAME structure (same `slug`, `date`, block count, block
`type`s, `src`/URLs) and translated human-readable text; THREE pilot files are
committed (`content/fa/<slug>.json`, `content/th/<slug>.json`,
`content/ar/<slug>.json`) for the re-targeted pilot slug (D-11a-10);
`feed.json` regenerates to 26 EN + 3 non-EN = 29 entries; the language switcher
offers EN + fa/th/ar (endonyms); the post header no longer shows the raw ISO

## Interfaces (mandatory — a milestone without these is not ready)

### Create: apps/blog/tools/translate.js (Node 20, no external npm deps)

    CLI:  node tools/translate.js --lang <fa|th|ar> [--slug <slug>] [--dry-run]
    Reads ONLY content/en/<slug>.json (the canonical EN envelope).
    Writes   content/<lang>/<slug>.json (g1: same structure, translated text).
    Requires the API key via KEY_ENV; if absent -> clear error, exit non-zero,
    and (git-safety) NO file is written. --dry-run prints the diff summary and
    writes nothing.

    g1 = per-block strings ONLY:
      TRANSLATE:  top-level `title`; and, per block,
                  paragraph.content, quote.content, image.caption,
                  embed.content, table.content, footnotes.content
                  (whatever text-bearing string fields that block type has;
                  the live set is paragraph/quote/image/embed/table/footnotes).
      NEVER TOUCH: `slug`, `lang`, `date`, block `type`, image/embed `src`
                  (URLs), and — this is the critical one — the HTML TAGS,
                  ATTRIBUTES and URLS *inside* any `content` string.
      `content` fields are HTML (they carry <a href>, <img>, entities like
      &#8217;). Translate ONLY the human-readable text nodes; preserve every
      tag, attribute and href BYTE-FOR-BYTE.
      g1 CHARACTER-REFERENCE NOTE (clarified by the 11a pilot): the contract
      binds STRUCTURE (tags/attributes/URLs), not CHARACTER REFERENCES. DeepL
      decodes numeric references to the target language's punctuation (e.g.
      `&#8216;`/`&#8217;` -> real `'`/`'`, or `«»` in fa/ar). This is a
      semantic no-op and is ACCEPTED. Validation checks TAG-token invariance
      and URL invariance; it does NOT require character-reference invariance.
      Assert tag-count invariance per field; abort the run on mismatch rather
      than writing a corrupted envelope. The envelope's `lang` becomes <lang>.
    Determinism / idempotence: re-running with the same inputs and same
    provider response must not churn the file. Output is pretty-printed JSON
    with 2-space indent (match the EN files' formatting).

## Decisions frozen for this milestone

- D-11a-1 (R2): the site is static; NO RSS/Atom/public data feed is built. The
  internal JSON list index (feed.json) is retained as the app's data source.
  Recorded in ROADMAP's "decided-not-to-do".
- D-11a-2 (m1): translations are PRE-GENERATED offline by tools/translate.js and
  committed; the app performs NO runtime translation; the API key is env-only
  and never committed/shipped.
- D-11a-3 (g1): only per-block human-readable text is translated; envelope
  structure (slug/date/block types), image/embed src, and ALL HTML tags/
  attributes/URLs inside content are preserved. CHARACTER REFERENCES are NOT
  required to be preserved (provider decodes them to target punctuation; a
  semantic no-op) — see the g1 CHARACTER-REFERENCE NOTE above.
- D-11a-4: the pilot translates ONE slug into fa, th, ar (one blog per language).
- D-11a-5: feed.json is regenerated by generate-index.js (which already walks
  all languages); generate-index.js itself is NOT modified.
- D-11a-6 (SUPERSEDED by D-11a-8): the original "NO UI change; switcher stays
  EN-only" fence was lifted by the human re-scope.
- D-11a-7: a failed/ambiguous translation aborts WITHOUT writing (no corrupt or
  half-translated envelope is ever committed).
- D-11a-8 (SCOPE AMENDMENT, Decision 2(ii)): 11a WIDENS the switcher to offer
  the content languages EN + fa/th/ar, so the pilot is end-to-end testable
  BEFORE the batch phase. nav.js LANGS = endonyms (English / فارسی / ไทย /
  العربية). Labels are content (B-5); per-language review owed.
- D-11a-8a (Decision 1(a)): translate.js DEFAULT_SLUG is re-pointed to the
  re-targeted pilot slug; hash-state.js PILOT_SLUG is left UNCHANGED.
- D-11a-9: the post header no longer renders the raw ISO date; the meta line is
  the bare language code (`EN`/`FA`/`TH`/`AR`). The date was already removed
  from the list view in 10c; this removes the stale machine timestamp from the
  post header (a pre-existing defect, not a regression).
- D-11a-10: the pilot slug is RE-TARGETED from `update` to
  `a-contemporary-history-of-the-muslim-world-11-afghanistan-3` (the human's
  decision: `update` is a non-blog announcement, already deny-listed in 10c).
- D-11a-11 (DEFERRED to 11b): LOCAL IMAGE STORAGE. The 326 image blocks in the
  EN corpus (309 from twolegsbadblog.wordpress.com; 17 external) still point at
  REMOTE URLs. Migrating the 309 WordPress-hosted images into a local store
  (`assets/img/posts/<slug>/`) with a download+rewrite tool is a SEPARATE
  milestone (11b). Decision (this chat): 11b covers ONLY the 309 WordPress-hosted
  images; the 17 external/copyrighted images stay as remote links. alt-text
  strategy (`"Blog image"` placeholder today) is also deferred to 11b.
