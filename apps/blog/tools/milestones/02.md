# Milestone 02: Block Parser

## Objective

Create the second stage of the offline Node.js build pipeline. This script reads the raw cached WordPress data, parses the HTML content into the standardized JSON Block structure defined in LOCKED_DECISIONS.txt, and outputs a clean JSON file for the frontend to consume.

## Files to Create

1. `zabon/apps/blog/tools/parser.js`

## Files to Modify

- None. (It will read from `tools/cache/` and write to `assets/data/`).

## Files I will NOT touch

- Any files outside `zabon/apps/blog/`.
- `zabon/apps/blog/assets/js/` (Frontend JS is not touched yet).

## Hard Constraints (from LOCKED_DECISIONS.txt)

- **Node 20 LTS**: No external npm dependencies. Use native Node APIs.
- **Block Types**: The parser must map WordPress HTML into these exact block types: `paragraph`, `heading`, `image`, `gallery`, `quote`, `pullquote`, `list`, `table`, `divider`, `embed`, `resourceList`, `callout`, `footnotes`, `attachment`.
- **Output Format**: The output must be a JSON array of post objects. Each post must have `slug`, `title`, `date`, `lang` (defaulting to 'en' for pilot), and `blocks` (the parsed array).
- **Output Path**: Write the final JSON to `zabon/apps/blog/assets/data/posts.json`.

## Test Checklist

1. **File Tree Check**:
   - Run: `ls zabon/apps/blog/tools/parser.js`
2. **Execution Check**:
   - Run from REPO_ROOT: `node zabon/apps/blog/tools/parser.js`
   - It must read `tools/cache/raw-posts.json` and generate `assets/data/posts.json`.
3. **Schema Validation**:
   - Open `zabon/apps/blog/assets/data/posts.json`.
   - Verify the structure: `[ { "slug": "...", "title": "...", "blocks": [ { "type": "paragraph", "content": "..." }, ... ] } ]`.
   - Verify that no raw HTML tags (like `<p>` or `<h2>`) exist in the `content` fields; they must be parsed into the `type` property.
