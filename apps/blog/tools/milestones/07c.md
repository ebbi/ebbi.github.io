# Milestone 07c: Font selection in Settings (traditional / modern + default book-reader base)

## Scope fence (read first)

This milestone adds a FONT-FAMILY control to the app's Settings panel — the
existing 07 drawer (`#app-panel`) — letting the reader choose between a
TRADITIONAL and a MODERN font, with a sensible DEFAULT base font suited to a
book-reader app. It touches `index.html` (add the control to the drawer),
`assets/css/style.css` (font-family token definitions + additive control
classes), a JS module (a new `font.js` mirroring `theme.js`, OR an addition to
`shell.js`), and the ROADMAP/CURRENT pointer. It does NOT touch the extraction
seam (`tools/import-post.js`, frozen through D-Tool-29), any
`content/**/*.json`, `feed.json`, `renderer.js` block mappings, `router.js`,
`app.js` route/render logic, `nav.js`, TTS/`tts.js`, or the typographic SYSTEM
(that is 07d — 07c depends on 07d). It must NOT change the meaning of any
existing class. It is a preference + token milestone: it re-points the family
tokens defined by 07d.

Relationship to 07d: 07d defines --font-body / --font-heading / --font-mono and
the typographic system; 07c lets the reader CHOOSE which FAMILY feeds
--font-body (and, optionally, headings), persisted like the theme pref (07b).

## Objective

When this milestone is done:

- the drawer contains a Font control offering at least **Traditional** and
  **Modern** families, with an accessible name, peer of the theme control
  (#theme-nav) and the language switcher (#lang-nav),
- a sensible **DEFAULT base font** for a book-reader app is applied on first
  run (no stored pref): a comfortable serif designed for reading (e.g. a
  system serif stack, or an available reading serif) — chosen so it needs no
  network font fetch and degrades gracefully,
- selecting a family re-points the font-family token(s) defined by 07d and
  re-renders the post body immediately,
- the choice **persists** across reloads under ONE localStorage key (same
  pattern as the theme pref, 07b) and is applied BEFORE first paint (no flash
  of the wrong font) — coordinated with the existing pre-paint theme apply,
- the control does not regress RTL, focus visibility, the 07 drawer, or the
  theme toggle,
- and when fonts are not web-loaded (offline / no webfont), the stacks fall
  back gracefully to a readable system font (no invisible text).

## Decisions frozen for this milestone

- F-1: The font control lives in the 07 drawer (#app-panel) — the "Settings
  panel". No new panel is introduced.
- F-2: Family keys are `traditional` and `modern` (extensible). The DEFAULT
  (no stored pref) is a book-reader-appropriate base font (a reading serif
  stack with graceful system fallback). Whether headings follow the body font
  or keep a separate family is specified here and recorded in the handoff.
- F-3: Persistence via localStorage under ONE key; applied BEFORE first paint,
  coordinated with the theme pre-paint apply (single early-apply source).
- F-4: Fonts are SYSTEM stacks (no network fetch) unless a webfont is
  deliberately added; if added, it must be local/self-hosted and degrade
  gracefully (no invisible text, no layout-shifting fetch).
- F-5: The control re-points font-family TOKENS only (defined by 07d); no
  component class changes meaning, and no existing token is removed.
- F-6: Guarded init in app.js (font.js optional; app must not break if absent).

## Known issues the next chat must NOT mistake for bugs

- 07c chooses the font FAMILY; the typographic SYSTEM (measure, rhythm, scale,
  hyphenation) is 07d and must land first. A measure that is not yet tuned is
  not a 07c bug.
- System-stack fallback means the glyphs vary by OS; that is by design (no
  webfont fetch).
- Transport buttons / Player behaviour are out of scope (TTS/TTS2).
- Translations (11) must NOT start until the HUMAN GATE (detailed blog text
  review) is signed off.
