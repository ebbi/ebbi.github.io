# Milestone 04: Router & App Integration

## Objective

Implement the hash-based client-side router and wire up the main application logic. This milestone connects the data fetching (client-side loading of the pre-built JSON), the router (handling URL changes and language detection), and the renderer (displaying the content). This makes the blog a functional Single Page Application (SPA) compatible with GitHub Pages.

## Hard Constraints (from LOCKED_DECISIONS.txt)

- **Hash Routing**: URLs must be in the format `#/en/post/slug` or `#/fa/post/slug`. This is mandatory for GitHub Pages compatibility.
- **Language Detection**: The router must parse the language prefix from the hash (e.g., `en`, `fa`, `ar`, `th`) and update the `<html lang="..." dir="...">` attributes dynamically.
- **Data Loading**: `app.js` must fetch `assets/data/posts.json` (or specific post JSONs if split) and pass the data to `BlogRenderer`.
- **Script Loading**: Ensure `index.html` loads scripts with `defer` or at the end of the `<body>` to ensure DOM readiness.

1. **File Tree Check**:
   - Run: `ls zabon/apps/blog/assets/js/router.js zabon/apps/blog/assets/js/app.js zabon/apps/blog/index.html`
2. **HTML Script Check**:

3. **Browser Routing Check**:
   - Open `index.html` in the browser.
   - Navigate to `#/en/post/jews-in-palestine-before-israel` (assuming the pilot slug exists in the JSON).
   - Verify the page renders the post content.
   - Verify the `<html>` tag updates to `lang="en" dir="ltr"`.
4. **404 Fallback Check**:
   - Navigate to a non-existent hash like `#/en/post/does-not-exist`.
   - Verify the app gracefully shows a "Not Found" message instead of crashing.
