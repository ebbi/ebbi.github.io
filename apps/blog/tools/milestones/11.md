# Milestone 11: Translations & i18n UI

## Scope fence (read first)

This milestone wires the NON-EN content languages into the UI: the language
switcher (nav.js) must offer the languages that actually have content, route
to them, and the list/post views must render their `lang` correctly (including
the current EN fallback for language-agnostic slugs per D3). It is a UI/i18n
milestone. It does NOT touch the extraction seam (`tools/import-post.js`, frozen
through D-Tool-29), `generate-index.js`, `hash-state.js`, `test-integrity.js`,
or any `content/en/*.json`. It does NOT add new content files (translation
ingestion is a separate content milestone if/when translations exist). It does
NOT touch `renderer.js` block mappings (B1) and does NOT re-do C1b-18 series
ordering or 10b's collapsible list (those are frozen). Whether real
translations beyond EN exist at this point MUST be measured at recon; if the
non-EN `content/<lang>/` dirs are empty, this milestone ships the i18n UI +
the switcher contract only, and records the empty-translation state as a Known
issue rather than inventing content.

## Objective

When this milestone is done, the reader can switch among the languages the app
actually ships, sees the list/empty-state and post views in that language, and
the language switcher reflects (and stays in sync with) the current route. The
EN fallback for a language-agnostic slug is preserved and visible. No EN
behaviour regresses; the 08/09/10b list and post views and B1 block types are
unchanged.
