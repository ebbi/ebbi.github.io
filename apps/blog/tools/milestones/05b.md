# Milestone 05b: Search UI

## Objective

Implement the client-side Vanilla JS fuzzy search UI. This module will read the `search-index.json`, listen to input events on a search field, and dynamically filter the post list view without reloading the page.

## Files to Create

1. `apps/blog/assets/js/search.js`

## Files to Modify

- `apps/blog/index.html` (Add a search input field inside the `<header>` or above the post list).
- `apps/blog/assets/js/app.js` (Integrate the search module into the list view rendering logic).

## Files I will NOT touch

- Any files outside `apps/blog/`.
- `apps/blog/tools/` (Node.js tooling is not touched).
- `apps/blog/assets/data/posts.json` or `search-index.json` (Read-only).

## Hard Constraints (from LOCKED_DECISIONS.txt)

- **Vanilla JS only**: No frameworks, no external search libraries (e.g., Fuse.js). Implement a simple, case-insensitive substring match on `title` and `excerpt`.
- **Debouncing**: The search input must be debounced (e.g., 300ms) to prevent excessive DOM re-renders on every keystroke.
- **State Preservation**: The search query should ideally be reflected in the URL hash (e.g., `#/en?q=query`) so it survives page refreshes, but a simple in-memory filter is acceptable for this milestone if hash updates are complex.
- **Accessibility**: The search input must have an `aria-label="Search posts"`.

## Test Checklist

1. **File Tree Check**:

2. **Syntax Check**:
   - Run: `node -c apps/blog/assets/js/search.js`
3. **Manual Browser Check**:
   - Open `apps/blog/index.html` in the browser.
   - Verify the search input is visible on the home/list view.
   - Type a word present in the pilot post title (e.g., "Palestine" or "Israel").
   - Verify the post list instantly filters to show only matching posts.
   - Clear the search input. Verify the full list restores.
