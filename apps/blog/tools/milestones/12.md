# Milestone 12: TTS Player Controls (speed, pitch, voice) + on-toolbar Language & Font icons

## Scope fence (read first)

This milestone extends the TTS / TTS2 transport (both frozen) into a
real PLAYER. It adds:

- a PLAYBACK SPEED control (5 named steps: Slower / Slow / Normal / Fast /
  Faster) AND a continuous slider (0.5x - 2.0x) that snaps to a named step;
- a PITCH control with a "Natural pitch" AUTO heuristic (default ON) plus a
  manual override slider;
- a VOICE picker that lists voices for the CURRENT route language, ranked by a
  documented quality heuristic, with the best auto-selected and a "Test voice"
  preview;
- a LANGUAGE icon directly on the bottom transport toolbar (same language set
  as the drawer switcher);
- a FONT icon directly on the bottom transport toolbar (cycles Default /
  Traditional / Modern via BlogFont.set).

It touches: `index.html` (toolbar markup + script), one NEW JS module
(`assets/js/speech-settings.js`), `tts.js` (consume the settings at utterance
build — ADDITIVE), `app.js` (guarded wiring of the new controls), ONE
additive `style.css` block, the ROADMAP, and the CURRENT pointer.

It does NOT touch the extraction seam (`tools/import-post.js`, frozen through
D-Tool-29), any `content/**/*.json`, `feed.json`, `renderer.js`, `router.js`
(the route vocabulary + RTL set are unchanged), the extraction/index/hash/test
tools, `LOCKED_DECISIONS.txt`, or `CONTEXT.md`. It does NOT re-own the
language switcher logic (nav.js) or the font family (font.js) — it DELEGATES
to their public APIs. It does NOT add a server-side audio pipeline, cached
audio, or bundled voice assets; voices are platform-provided (X-1).

## Objective

When this milestone is done:

- the reader can set playback SPEED (named steps + slider), persisted across
  reloads;
- PITCH defaults to a "Natural pitch" auto heuristic (documented, small
  compensation) with a manual override;
- the reader can pick a VOICE for the current language from those the platform
  actually provides, with the highest-quality one auto-selected by a
  documented ranking, remembering the choice PER LANGUAGE;
- the bottom toolbar carries a LANGUAGE icon (navigates identically to the
  drawer switcher) and a FONT icon (cycles the reading family);
- speed / pitch / voice changes apply to the NEXT spoken sentence (the
  chunked engine) WITHOUT restarting the post;
- every new control is keyboard-accessible, correctly labelled, and degrades
  gracefully when `speechSynthesis` / voices are unavailable (X-5 mirror).

## Decisions frozen for this milestone

- D-12-1 (speed): Playback rate via `utterance.rate`. Five NAMED steps
  (Slower 0.6 / Slow 0.8 / Normal 1.0 / Fast 1.25 / Faster 1.6) AND a
  continuous slider 0.5-2.0. The slider value maps to the nearest named step
  when within a small epsilon; otherwise a custom rate. Persisted under ONE
  localStorage key ("zabon-blog-tts-rate"). Range 0.5-2.0 chosen because
  `rate` beyond ~2 is unintelligible across engines (documented).
- D-12-2 (pitch): `utterance.pitch` in 0.5-1.5. TWO modes:
  "auto" (DEFAULT) applies a DOCUMENTED "natural pitch" heuristic — a small
  upward compensation at the extreme rates (|rate-1|), because engines tend to
  sound dull/compressed at high rate and sluggish at low rate; and "manual"
  uses the reader's pitch slider. The heuristic is a curve, NOT a claim of
  engine quality improvement; the milestone states this plainly. Persisted
  under ONE key ("zabon-blog-tts-pitch") + a mode key.
- D-12-3 (voice): Populate voices from `speechSynthesis.getVoices()` filtered
  by the current route language's BCP-47 prefix (en/fa/ar/th). RANK by a
  DOCUMENTED heuristic (localService preferred; then a curated name allow-list
  e.g. "Natural"/"Neural"/"Online"/"Google"/"Microsoft"; then default flag;
  then regional specificity; then stable order). The top-ranked voice
  AUTO-selects; the reader may override; the choice is remembered PER LANGUAGE
  under ONE key ("zabon-blog-tts-voice" = a JSON map lang->voiceURI). Handle
  the async voice list: if empty at init, wait for `voiceschanged`.
- D-12-4 (language icon): the toolbar language icon offers the SAME language
  set as the drawer switcher and navigates via the SAME href rule
  (buildLangHref semantics; single source). Changing it is a normal route
  change (router-owned RTL/lang), NOT a TTS-side language set.
- D-12-5 (font icon): the toolbar font icon calls BlogFont.set() to cycle the
  known family keys ("" -> traditional -> modern -> ""); font.js remains the
  single owner of the family and its persistence.
- D-12-6 (apply-on-next-sentence): because tts.js speaks sentence-by-sentence,
  speed/pitch/voice changes are read at each utterance build and therefore
  take effect at the NEXT sentence boundary WITHOUT restarting the post.
- D-12-7 (graceful): if `speechSynthesis`/`getVoices` are unavailable, the new
  controls are inert/disabled and the app is unaffected (X-5 mirror). Every
  read by tts.js of BlogSpeech is GUARDED so tts.js alone is unchanged in
  behavior when BlogSpeech is absent.
- D-12-8 (a11y): every icon is a real <button> with an accessible name; the
  settings popover uses aria-expanded/aria-controls + the `hidden` attribute
  (10b convention); the voice/speed controls are native <select>/<input>;
  new animation respects prefers-reduced-motion.

## Known issues the next chat must NOT mistake for bugs

- Web Speech API exposes NO voice-quality score; "highest quality" is a
  DOCUMENTED heuristic (D-12-3), not ground truth. A reader override is final.
- Pitch cannot make a poor voice good; D-12-2 is a small compensation curve.
- Some engines ignore `pause()`/`resume()` (the TTS chunking fix already
  handles the post-level case); rate/pitch/voice support varies by engine.
- The list view keeps the transport inert (X-3/X-6); that is NOT a regression.
- Available voices differ by browser/OS; the voice list is platform-provided.
