# Milestone 06: Navigation & Header

## Objective

Build a robust, responsive header component with a language switcher. The language switcher must update the URL hash to the selected language while preserving the current view (e.g., switching from `#/en/post/slug` to `#/fa/post/slug`).

## Files to Create

1. `apps/blog/assets/js/nav.js`

## Files to Modify

- `apps/blog/index.html` (Replace the basic placeholder nav with a proper `<header>` structure).
- `apps/blog/assets/css/style.css` (Add basic, responsive header and language switcher styles).
- `apps/blog/assets/js/app.js` (Initialize the nav module).

## Files I will NOT touch

- Any files outside `apps/blog/`.
- `apps/blog/tools/` (Node.js tooling).
- `apps/blog/assets/data/` (Data files).

## Hard Constraints (from LOCKED_DECISIONS.txt)

- **Vanilla JS only**: No frameworks.
- **Language Support**: The switcher must display the supported UI languages: `en`, `fa`, `ar`, `th`.
- **Hash Preservation**: If the user is on `#/en/post/jews-in-palestine-before-israel` and clicks "FA", the URL must become `#/fa/post/jews-in-palestine-before-israel`. If on the home list `#/en`, it becomes `#/fa`.
- **RTL Awareness**: The header layout must gracefully adapt when the router sets `dir="rtl"` on the `<html>` tag (e.g., using CSS logical properties like `margin-inline-start` instead of `margin-left`).
