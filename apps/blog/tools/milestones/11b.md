### Create: apps/blog/tools/localize-images.js (Node 20, no external npm deps)

    CLI:  node tools/localize-images.js [--lang <en|fa|th|ar>] [--slug <slug>]
          [--dry-run] [--force] [--report] [--yes]
    Network tool. SEPARATE from the frozen extraction seam (import-post.js);
    this does NOT touch import-post.js.
    Behavior:
      1. Scan the TARGET content/<lang>/<slug>.json (or ALL its *.json when
         --slug omitted) for image references: (a) every `image` block's
         top-level `src`; (b) every image-file attr (`src`, `data-orig-file`,
         `data-large-file`) inside a text/HTML field.
      2. For each reference whose host == twolegsbadblog.wordpress.com: download
         the file (cache-first; reuse a download cache dir) and store it under
         assets/img/posts/<slug>/<YYYY>/<MM>/<basename> (P1/P2).
      3. DEDUP by FULL source path (P3): two blocks referencing the same path
         share ONE local file. Basename-only dedup is FORBIDDEN.
      4. Rewrite the reference in content/<lang>/<slug>.json from the remote URL
         to the local relative path (block `src` AND inline image-file attrs).
      5. Hosts in the EXTERNAL ALLOW-LIST (below) are LEFT UNTOUCHED. Non-image
         links (`href`, `data-permalink`) are NEVER touched.
      6. Idempotent (P4); --force re-downloads.
      7. --dry-run prints the plan and writes NOTHING.
      8. --report prints a summary (must show broken local refs = 0).
      9. FAILURE POLICY: any in-scope download failure aborts WITHOUT rewriting;
         exit non-zero. No half-rewritten file.
    For translations (--lang fa|th|ar), src is re-synced to the SAME local store
    path as EN (0 downloads when the store already exists) — see P6.
    Output JSON re-serialized deterministically (2-space indent) — UNCHANGED for
