Quote content, cite-carrying: blockFromFragment("quote") collects BOTH <p class="wp-block-paragraph"> bodies AND <cite> text from the source, in source order, skipping empties, joined by "\n"; falls back to the blockquote inner HTML if neither is present. (D-Tool-18; recorded as a deliberate, narrow extension of the D-Tool-9 seam freeze to correct the L-007 content loss.)
Bare-paragraph rule: extractHtmlBlocks() gains one entry in its TOP list for a bare <p> directly inside entry-content: regex /<p\b(?![^>]*\bclass="[^"]*\bwp-block-)[^>]*>[\s\S]*?<\/p>/i, kind "paragraphBare", handled in blockFromFragment() identically to "paragraph" (strip tags, keep entities, trim -> { type:"paragraph", content:<str> }). It matches a <p> whose class attribute is absent OR lacks "wp-block-"; it does NOT re-capture wp-block-paragraph (owned by the existing entry) nor any <p> nested inside a wrapper block (blockquote/figure/div.wp-block-*), which the skip-and-continue loop consumes whole first. Rationale: some live posts render their body as bare <p> with no wp-block-* markers (L-008, `update`); without this rule the whole post is unrepresentable and update.json cannot exist. (D-Tool-19; the second deliberate, narrow extension of the D-Tool-9 seam freeze, after D-Tool-18.)
Bare-paragraph-image rule: extractHtmlBlocks() TOP list gains an entry, placed AFTER the wp-block-paragraph entry and BEFORE the paragraphBare entry, matching /<p\b(?![^>]*\bclass="[^"]*\bwp-block-)[^>]*>\s*<img\b[^>]*\/?>\s*<\/p>/i, kind "imageBareP", handled in blockFromFragment() by reusing the existing image shape ({ type:"image", src:<img src verbatim>, caption:"" }). It matches a <p> whose class is absent or lacks "wp-block-" AND whose entire content is a single <img>. Rationale: legacy WP.com emits inline images as bare <p><img></p> with no wp-block-image wrapper; the D-Tool-19 bare-<p> rule otherwise swallowed them as paragraph blocks, so a reader would see raw <img> markup instead of a picture (L-009, part-22, 4 images). Placing this entry before paragraphBare claims the case first; the paragraphBare regex is left byte-identical so D-Tool-19 prose behaviour is unchanged.
